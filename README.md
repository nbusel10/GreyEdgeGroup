# The GreyEdge Group

Marketing site for The GreyEdge Group — thermal utility master planners.

React 19 + Vite + TypeScript + Tailwind v4, built to a plain static `dist/` so it can
be hosted anywhere.

## Getting started

Node 22 is pinned via `mise`. If you use it, `mise install` picks up the right version;
otherwise any Node 22+ works.

```bash
pnpm install
pnpm dev          # http://localhost:5173
```

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Dev server with HMR |
| `pnpm build` | Generates sitemap and share card, typechecks, builds to `dist/` |
| `pnpm preview` | Serves the built `dist/` locally |
| `pnpm import:wp` | Re-pulls content from the WordPress site (see below) |

## How content works

All copy lives in `src/content/` as plain TypeScript — no CMS, no database, no plugins
to keep updated. Editing the site means editing those files, and every change is
reviewable in a git diff.

Two kinds of content files live there:

**Imported.** `projects.ts`, `team.ts`, and `images.ts` are generated by
`scripts/import-wp.mjs` from the WordPress site's REST API. The script also downloads
every image into `public/images/`, so the live site has no runtime dependency on the
WordPress host. Project stats (square footage, building count) live in Elementor
widgets that the REST API doesn't expose, so the importer scrapes those from the
rendered pages and prints a warning for anything it can't find rather than silently
dropping it. Re-running the importer overwrites these three files, so hand-edits to
them will not survive.

**Hand-written.** Everything else — `site.ts`, `advantage.ts`, `process.ts`,
`challenges.ts`, `leadership.ts`, `about.ts`, `insights.ts` — is narrative copy that
was written for this build. The importer never touches these.

## Deploying

`pnpm build` produces a static `dist/`. Point any static host at it.

The app uses real client-side routes, so the host has to serve `index.html` for unknown
paths. `public/_redirects` handles this on Netlify and Cloudflare Pages; other hosts
need the equivalent SPA fallback configured.

## Contact form

The form posts to `VITE_FORM_ENDPOINT` if set (see `.env.example`), and otherwise uses
Netlify Forms markup, which works with no configuration on Netlify. Pointing it at a
CRM later means setting one environment variable.

## Checks

Both need a server running — dev on `:5173`, or set `BASE` to a preview URL.

```bash
node scripts/check-links.mjs   # crawls every route: broken links, anchors, alt text, page metadata
node scripts/shots.mjs         # screenshots every route at 1440/1280/1024/768/375, flags overflow and console errors
```
